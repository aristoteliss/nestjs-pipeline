Η έκδοση 0.2.2 αλλάζει τον τρόπο με τον οποίο αποκρίνονται τα exception filters των `@nestjs-pipeline/zod`, `/casl`,
`/feature-flags`, `/idempotency` και `/rate-limit`, ώστε μία κοινή διαδρομή κώδικα να εξυπηρετεί
το Express και το Fastify. Η δήλωσή τους χρειάζεται προσαρμογή, και τα πέντε πακέτα προσθέτουν
ένα peer dependency `@nestjs/core` `^11.0.0`.

## Τα exception filters αποκρίνονται μέσω του HTTP adapter του Nest <a id="exception-filters-reply-through-nests-http-adapter"></a>

Τα `ZodValidationFilter`, `UnauthorizedActionFilter`, `FeatureDisabledFilter`,
`IdempotencyConflictFilter` και `RateLimitExceededFilter` λαμβάνουν το `HttpAdapterHost` του Nest και
απαντούν με `httpAdapter.reply` (το `RateLimitExceededFilter` ορίζει επίσης το `Retry-After` μέσω
του adapter). Στο Fastify, ένα σφάλμα που προκύπτει σε ένα Nest middleware φτάνει στο φίλτρο με την ακατέργαστη (raw)
απάντηση του Node· τα φίλτρα αποκρίνονται και σε αυτό, αντί να προκαλούν σφάλμα και να αφήνουν το αίτημα
χωρίς απάντηση.

Δηλώστε κάθε φίλτρο ως provider, ώστε το Nest να κάνει inject το host:

```typescript
import { Module } from '@nestjs/common';
import { APP_FILTER } from '@nestjs/core';
import { ZodValidationFilter } from '@nestjs-pipeline/zod';

@Module({
  providers: [{ provide: APP_FILTER, useClass: ZodValidationFilter }],
})
export class AppModule {}
```

ή περάστε το στο `main.ts`:
`app.useGlobalFilters(new ZodValidationFilter(app.get(HttpAdapterHost)))`. Ένα φίλτρο που δημιουργείται
χωρίς το host (`new ZodValidationFilter()`) δεν γίνεται compile. Το `FeatureDisabledFilter`
δέχεται τις επιλογές του ως δεύτερο όρισμα:
`new FeatureDisabledFilter(app.get(HttpAdapterHost), options)`.
