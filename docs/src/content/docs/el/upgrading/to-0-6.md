:::tip[Το κύριο αποθετήριο είναι το ddd-cqrs]
Από την έκδοση 0.6.1, τέσσερα πακέτα `@nestjs-pipeline` δεν έχουν δικό τους κώδικα. Επανεξάγουν
τα πακέτα `@cqrs-ddd` του [ddd-cqrs](https://github.com/aristoteliss/ddd-cqrs) στην ίδια
έκδοση. Μπορείτε να κρατήσετε τα ονόματα `@nestjs-pipeline` ή να χρησιμοποιήσετε απευθείας τα
πακέτα `@cqrs-ddd`. Τα πακέτα δεν έχουν αποσυρθεί.
:::

| Πακέτο | Η 0.6.1 επανεξάγει |
| --- | --- |
| `@nestjs-pipeline/core` | `@cqrs-ddd/pipeline` και `@cqrs-ddd/nestjs` |
| `@nestjs-pipeline/correlation` | `@cqrs-ddd/pipeline-correlation` και `@cqrs-ddd/nestjs/correlation` |
| `@nestjs-pipeline/job-context` | `@cqrs-ddd/pipeline-job-context` και `@cqrs-ddd/nestjs/job-context` |
| `@nestjs-pipeline/cqrs-ddd` | `@cqrs-ddd/nestjs`, από τα ίδια τρία entry points |

Τα άλλα πακέτα `@nestjs-pipeline` (`audit`, `cache`, `casl`, `deadletter`, `feature-flags`,
`idempotency`, `opentelemetry`, `rate-limit`, `resilience`, `tenant`, `zod`) μένουν στην 0.4.3.
Απαιτούν το `@nestjs-pipeline/core` 0.4.x. Οι απαιτήσεις μένουν ίδιες: Node.js 22.12 ή νεότερο
και NestJS 12.

## Παραμονή στην 0.4.x

Μια εφαρμογή στην 0.4.x συνεχίζει να λειτουργεί χωρίς αλλαγή. Ορίστε τις εκδόσεις, γιατί το
tag `latest` των τεσσάρων πακέτων είναι η 0.6.1:

```bash
pnpm add @nestjs-pipeline/core@^0.4.3 @nestjs-pipeline/correlation@^0.4.4 \
  @nestjs-pipeline/job-context@^0.4.3
```

## Από την 0.4.x στην 0.6.1

**1. Αντικαταστήστε τα πακέτα behaviors.** Ένα πακέτο behavior της 0.4.x δεν λειτουργεί με το
core 0.6.1. Αντικαταστήστε κάθε `@nestjs-pipeline/<name>` με το `@cqrs-ddd/pipeline-<name>` 0.6.1:

```bash
pnpm remove @nestjs-pipeline/idempotency @nestjs-pipeline/audit
pnpm add @nestjs-pipeline/core@^0.6.1 @cqrs-ddd/pipeline @cqrs-ddd/core \
  @cqrs-ddd/pipeline-idempotency @cqrs-ddd/pipeline-audit
```

**2. Αλλάξτε τα modules.** Ένα behavior είναι provider της εφαρμογής. Το
`PipelineModule.forRoot()` δεν έχει τις επιλογές `behaviors`, `bootstrapLogLevel` και
`loggerProvider`, και το module δεν έχει `forRootAsync()` ή `forFeature()`. Ένα `ErrorFilter`
αντικαθιστά τα error filters των πακέτων.

**3. Αλλάξτε τα ονόματα που δεν εξάγονται.**

| 0.4.x | 0.6.1 |
| --- | --- |
| `HttpCorrelationMiddleware` | `CorrelationMiddleware` |
| `CORRELATION_OPTIONS`, `LOGGING_BEHAVIOR_LOGGER` | ένα injection token της εφαρμογής |
| `PIPELINE_BEHAVIORS_METADATA`, `PIPELINE_BEHAVIORS_OPTIONS_METADATA`, `PIPELINE_SKIPPED_BEHAVIORS_METADATA` | `pipelineOf(handler)` |

**4. Προσθέστε τα peers.** Τα `@nestjs-pipeline/correlation` και `@nestjs-pipeline/job-context`
απαιτούν τα `@cqrs-ddd/core`, `@cqrs-ddd/pipeline`, `@nestjs/core` και `@nestjs/cqrs`.

Ο οδηγός [Από το @nestjs-pipeline 0.4.x](https://aristoteliss.github.io/ddd-cqrs/el/guides/from-nestjs-pipeline/)
δίνει κάθε αλλαγή με ένα πλήρες module πριν και μετά.

## Από το `@nestjs-pipeline/cqrs-ddd` 0.5.0 στην 0.6.1

Τα entry points και τα exports δεν αλλάζουν. Εγκαταστήστε τα peers `@cqrs-ddd` στο `^0.6.1`:

```bash
pnpm add @nestjs-pipeline/cqrs-ddd@^0.6.1 @cqrs-ddd/core@^0.6.1 @cqrs-ddd/pipeline@^0.6.1
```

Δώστε το ίδιο εύρος σε κάθε προαιρετικό peer που εγκαθιστά η εφαρμογή, όπως το
`@cqrs-ddd/pipeline-zod`. Οι αλλαγές του `@cqrs-ddd` από την 0.5 στην 0.6 βρίσκονται στο
[CHANGELOG του ddd-cqrs](https://github.com/aristoteliss/ddd-cqrs/blob/master/CHANGELOG.md).
