:::tip[The main repository is ddd-cqrs]
From 0.6.1, four `@nestjs-pipeline` packages have no code of their own. They re-export the
`@cqrs-ddd` packages of [ddd-cqrs](https://github.com/aristoteliss/ddd-cqrs) at the same
version. You can keep the `@nestjs-pipeline` names, or use the `@cqrs-ddd` packages directly.
The packages are not deprecated.
:::

| Package | 0.6.1 re-exports |
| --- | --- |
| `@nestjs-pipeline/core` | `@cqrs-ddd/pipeline` and `@cqrs-ddd/nestjs` |
| `@nestjs-pipeline/correlation` | `@cqrs-ddd/pipeline-correlation` and `@cqrs-ddd/nestjs/correlation` |
| `@nestjs-pipeline/job-context` | `@cqrs-ddd/pipeline-job-context` and `@cqrs-ddd/nestjs/job-context` |
| `@nestjs-pipeline/cqrs-ddd` | `@cqrs-ddd/nestjs`, from the same three entry points |

The other `@nestjs-pipeline` packages (`audit`, `cache`, `casl`, `deadletter`,
`feature-flags`, `idempotency`, `opentelemetry`, `rate-limit`, `resilience`, `tenant`, `zod`)
stay at 0.4.3. They require `@nestjs-pipeline/core` 0.4.x. The requirements stay the same:
Node.js 22.12 or later and NestJS 12.

## Stay on 0.4.x

An application on 0.4.x keeps working without a change. Pin the versions, because the
`latest` tag of the four packages is 0.6.1:

```bash
pnpm add @nestjs-pipeline/core@^0.4.3 @nestjs-pipeline/correlation@^0.4.4 \
  @nestjs-pipeline/job-context@^0.4.3
```

## From 0.4.x to 0.6.1

**1. Replace the behavior packages.** A 0.4.x behavior package does not work with core
0.6.1. Replace each `@nestjs-pipeline/<name>` with `@cqrs-ddd/pipeline-<name>` 0.6.1:

```bash
pnpm remove @nestjs-pipeline/idempotency @nestjs-pipeline/audit
pnpm add @nestjs-pipeline/core@^0.6.1 @cqrs-ddd/pipeline @cqrs-ddd/core \
  @cqrs-ddd/pipeline-idempotency @cqrs-ddd/pipeline-audit
```

**2. Change the modules.** A behavior is a provider of the application.
`PipelineModule.forRoot()` has no `behaviors`, `bootstrapLogLevel` or `loggerProvider`
option, and the module has no `forRootAsync()` or `forFeature()`. One `ErrorFilter` replaces
the error filters of the packages.

**3. Change the names that are not exported.**

| 0.4.x | 0.6.1 |
| --- | --- |
| `HttpCorrelationMiddleware` | `CorrelationMiddleware` |
| `CORRELATION_OPTIONS`, `LOGGING_BEHAVIOR_LOGGER` | an injection token of the application |
| `PIPELINE_BEHAVIORS_METADATA`, `PIPELINE_BEHAVIORS_OPTIONS_METADATA`, `PIPELINE_SKIPPED_BEHAVIORS_METADATA` | `pipelineOf(handler)` |

**4. Add the peers.** `@nestjs-pipeline/correlation` and `@nestjs-pipeline/job-context`
require `@cqrs-ddd/core`, `@cqrs-ddd/pipeline`, `@nestjs/core` and `@nestjs/cqrs`.

The guide [From @nestjs-pipeline 0.4.x](https://aristoteliss.github.io/ddd-cqrs/guides/from-nestjs-pipeline/)
gives each change with a complete module before and after.

## From `@nestjs-pipeline/cqrs-ddd` 0.5.0 to 0.6.1

The entry points and the exports do not change. Install the `@cqrs-ddd` peers at `^0.6.1`:

```bash
pnpm add @nestjs-pipeline/cqrs-ddd@^0.6.1 @cqrs-ddd/core@^0.6.1 @cqrs-ddd/pipeline@^0.6.1
```

Give each optional peer that the application installs, such as `@cqrs-ddd/pipeline-zod`, the
same range. The changes of `@cqrs-ddd` from 0.5 to 0.6 are in the
[CHANGELOG of ddd-cqrs](https://github.com/aristoteliss/ddd-cqrs/blob/master/CHANGELOG.md).
